# 后台采集与账号登录设计

## 目标

山竹洞察在不弹出 Chrome 的情况下完成手动和自动采集；Cookie 失效时明确提示，并允许用户主动登录抖音、小红书、视频号后台。

## 已确认方案

- 普通采集统一使用持久化无头 Chrome，继续复用 `data/browser-profile` 中的 Cookie。
- 服务进程每 15 分钟触发一次采集；同一时间只允许一个采集或登录任务。
- 网页每 30 秒检查状态。手动采集显示网页内状态弹窗，自动采集不打断用户。
- 三个平台卡片始终显示“登录/更新 Cookie”。主动登录才打开可见 Chrome，最多等待 5 分钟。
- Cookie 失效显示平台名、`需要登录` 和操作按钮。登录成功后等待下一次采集更新数据。
- 继续使用现有 ECharts。粉丝资产展示三平台 30 天趋势；账号健康卡展示各平台趋势。单数据点也必须可见。

## 边界

- 不接管用户系统 Chrome 配置，只使用项目独立浏览器档案。
- 不上传 Cookie，不提供远程登录，不新增第三方依赖。
- Headless 被平台风控拦截时显示采集异常，不自动弹出浏览器。
